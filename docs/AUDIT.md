审查日期：2026-09-30。范围：源码、本地特征 CSV、模型和离线回归测试；未录制或标注新的摄像头测试集。

补充修订：2026-10-08。本轮只改代码与既有数据，**不涉及任何新的真实人脸采集**：
修复可见性列空壳、让 `static_mode` 生效、补概率校准与拒识、补视频逐帧评测链路、
补分组划分字段，并修正名不符实的命名。因原始素材未变，`docs/` 中依赖真实采集的

## 已修复的问题

1. **规则引擎无法输出自然**：加载 CK+ 模型后，规则沿用模型的五类标签，而该模型没有 neutral。修复为规则使用独立的固定类别。
2. **加载模型不等于使用模型**：原流程默认规则但文档强调训练模型。新增 `--engine rules|ml`；明确引擎及类别差异；缺少模型时禁止伪装切换到 ML。
3. **概率标签可能错位**：原存储模型来自最好的一折，类别却来自最后一折。推理现以 estimator.classes_ 为准。
4. **部署只用某一折训练子集**：改为交叉验证后全量重训，保存样本数、人员数、特征版本和 CV 指标。
5. **评测输入校验不足**：缺失 subject_id 以前会退化到逐样本分组；现在拒绝缺列、非有限数值或不足两位人员的数据，固定 136 维特征顺序。
6. **规则分数过于尖锐**：移除 softmax 的额外 2.5 倍放大并减去最大值确保数值稳定；仍是相对分数，不能当成校准概率。
7. **人脸消失后残留旧预测**：清空平滑窗口；切换引擎同样清空。
8. **原测试并非端到端测试**：创建了卡通脸但没有调用检测，随机向量也没有进入 ML 分支。替换为 7 项确定性测试，覆盖类别隔离、ML 标签顺序、缺模型、平移缩放不变性、真实检测器空白帧、全量重训与人员验证。
9. 补充缺少的 joblib、tqdm、pyarrow 依赖；增加下载脚本、资源释放、数据忽略规则，纠正文档夸大描述。
10. **可见性列从空壳改为真实几何量**：MediaPipe FaceLandmarker 的 `visibility` / `presence`
    恒为 None，原实现用 `getattr(..., 0.0)` 兜底，`vis_0..vis_67` 被整列写成 0.0。
    现改为用关键点的归一化 x/y/z 构造 3D 点云、做 kNN 局部法线拟合与背向判定，
    得到逐点几何可见性（0~1），并新增 `vis_mean` 列。全表 27,307 行实测 68 列无一为常数，
    `corr(|yaw|, 逐行平均可见性) = -0.545`。注意它是**几何自遮挡估计，不是模型置信度**；
    若要模型原生的逐点置信度仍需换用输出该字段的模型（如 HRFFA 的 ONNX 方案）。
11. **`static_mode` 真正生效**：该参数过去只被接收、从未使用，批量脚本"以为是图像模式"、
    实时脚本也拿不到视频跟踪，且没有任何提示。现在它决定 MediaPipe 的
    `running_mode`（IMAGE / VIDEO），VIDEO 模式下自动维护严格单调的时间戳。
12. **补上概率校准与低置信拒识**：新增 `src/experiments/calibrate_model.py`，在独立校准集上
    比较 uncalibrated / temperature / sigmoid / isotonic 四种口径，按 proper scoring rule
    选型，并扫描拒识阈值输出"覆盖率 - 准确率"权衡。实测结论见下方"校准实测"一节。
13. **补上视频逐帧记录与汇总**：新增 `src/core/frame_recorder.py` 与
    `src/experiments/evaluate_video.py`，逐帧落盘 `{帧号, 时间, 检出, 延迟, yaw/pitch/roll,
    可见性, 预测, 分数, 是否拒识}` 并汇总检出率、姿态分桶、时序标签切换率等；
    `realtime_demo.py` 也新增 `--record-csv`，两者共用同一套记录口径。
14. **分组划分链路补全**：自采数据新增 `session_id` / `clip_id`（采集时按 `[N]` 可切分片段），
    CK+ 提取新增从文件名序列号解析出的 `clip_id`；`train_and_evaluate` 泛化为可选
    `subject_id` / `session_id` / `clip_id` 分组，可同时防住"同一人的连续帧跨折"这一最隐蔽的泄漏源。
15. **"68 点"锚点命名修正**：第 30 号点实际映射到 MediaPipe 195、并非解剖学鼻尖，
    原变量名 `nose_tip` 名不符实。已改为中性的 `anchor_pt` 并加注说明；
    **映射表本身仍不改动**（改映射会使既有 CSV 与模型权重全部失效，属于另一项升级工作）。
16. **HUD 明确标注置信度性质**：显示 `Calibrated Probabilities` 还是
    `Relative Scores (uncalibrated)`，低于阈值时显示 `UNKNOWN`（拒识判定放在时序平滑之后，
    避免逐帧分数抖动导致标签闪烁）。

### 校准实测（2026-10-08，`src/experiments/calibrate_model.py`）

协议：train 拟合基础 SVM → publicTest 前半拟合校准器 → publicTest 后半比较口径并选阈值 →
privateTest 仅用于最终报告（2,713 样本，全程未参与任何选择）。

| 口径 | Accuracy | ECE | Brier | NLL | 平均置信度 |
|---|---:|---:|---:|---:|---:|
| uncalibrated（原实现） | 69.81% | **0.0303** | 0.4670 | 0.9144 | 0.6724 |
| temperature (T=1.10) | 69.81% | 0.0624 | 0.4711 | 0.9167 | 0.6402 |
| sigmoid (Platt) | 70.00% | 0.0836 | 0.4713 | 0.9166 | 0.6166 |
| isotonic | 70.00% | 0.0654 | **0.4365** | **0.9055** | 0.6701 |

两点必须如实写进报告：
1. **ECE 与 proper scoring rule 的排序在这份数据上不一致** —— 未校准口径的 ECE 最低（0.0303），
   但等渗回归的 NLL / Brier 最优、准确率也略高。ECE 只看"最大概率"的分箱偏差，是诊断量，
   不能单独作为校准优劣的判据（脚本会显式打印这条提示），因此默认用 NLL 选型并把四个指标全部输出。
2. **在本数据集上，手写 softmax 的相对分数本来就接近校准**（温度缩放的最优解 T≈1.10，几乎为 1），
   所以"校准"带来的收益有限；它的主要价值是让数值**可以按把握解释**，并让拒识阈值有明确含义。

拒识权衡（privateTest，isotonic 口径）：阈值 0.55 时覆盖率 85.5%、被接受样本准确率 74.57%；
阈值 0.65 时覆盖率 56.8%、准确率 83.32%；阈值 0.75 时覆盖率 30.0%、准确率 93.13%
（不拒识时全量为 70.00%）。完整逐阈值表见 `data/fer2013_calibration.json`。

## 尚未解决的准确率限制

- **模型无自然类（高优先级）**：本地 CK+ 子集为 surprise 249、smile 207、disgust 177、frown 135、sad 84。没有 neutral，因此普通平静画面无法正确分类。需要补充真实数据并重训，不能凭空补标签。
- **皱眉、难过易混淆**：SVM 将 135 个皱眉样本中的 50 个判为厌恶，将 84 个难过样本中的 30 个判为皱眉。类别不平衡和单纯坐标特征可能是原因，需要对照实验确认。
- **规则容易受非表情动作影响**：张嘴讲话可能触发惊讶，固有眉间距、嘴唇形状会影响阈值。未做个人自然基线标定，也没有真实视频校准集。
- **“68 点”只是旧的自定义映射**：鼻部列表把第 30 点映射到 MediaPipe 195，实际上代码注释中的鼻尖应为 1；下巴轮廓分布也不是标准 68 点布局。为保留现有 CSV / 权重兼容性，本次没有静默修改映射（仅把名不符实的 `nose_tip` 改名为 `anchor_pt` 并加注）。改为正确映射时必须升级 schema、重新提取全部数据并重训。
- **仅平移和缩放归一化**：没有 roll 对齐或 yaw/pitch 透视补偿。头部姿态仅用于显示预警与离线分桶，仍然**不参与分类或拒识**；逐点可见性现已可计算并已落盘，但尚未作为特征进入分类器，也还没有"按可见性对关键点降权"的逻辑。若要验证其价值，需要在同一协议下做一次"含/不含可见性列"的特征消融实验。
- **图像模式而非视频跟踪**：已修复（见“已修复的问题”第 11 条）。VIDEO 模式需要统一的单调时间戳，现由 `_next_timestamp_ms` 自动维护；批量离线提取继续使用 IMAGE 模式，避免把互不相关的样本串成视频流。
- **数据来源与场景差异**：现有 CSV 的真实 subject_id 来源仍依赖导出文件名；未独立核实原始数据完整性。CK+ 特征评测不代表日常光照、眼镜、遮挡、肤色、年龄和连续讲话场景的效果。
- **概率未跨人校准**：已补上校准与拒识链路（见第 12 条与“校准实测”），但校准集仍来自 FER2013 官方划分、**不是按人员隔离的校准集**；在这份数据上未校准的相对分数本身已接近校准（最优温度 ≈1.10）。跨人可靠性仍需带 subject 标注的校准数据来验证。

## 建议的后续顺序

1. 用 `evaluate_video.py` 对**真实录制**的多姿态视频出数（正面 / 侧转 / 俯仰 / 远近 / 弱光），
   把逐帧 CSV 与汇总 JSON 作为任务C 的证据；这一步需要真实拍摄，是当前唯一还缺"数据"而非"代码"的环节。
2. 采集包含自然类的真实多人、多姿态数据（用 `--session` 记录拍摄时段），
   保留独立人员和拍摄时段作为最终测试集，并按 `clip_id` 分组评测。
3. 做一次"含/不含可见性列"的特征消融实验，确认可见性是否值得进入分类特征；
   若要按可见性对关键点降权或做抛点，应同时比较加权前后的大角度分组指标。
4. 纠正关键点映射和头部坐标系，升级数据 schema 并重新提取、训练。
5. 在独立校准集（最好按人员隔离）上重新标定拒识阈值、个人自然基线、说话排除与时序策略，
   实测准确率、覆盖率与延迟。
